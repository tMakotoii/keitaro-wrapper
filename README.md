# Обёртка для Keitaro

Веб-приложение для создания и управления кампаниями в Keitaro. При создании кампания получает два потока: гео-редирект на Google и поток офферов.

## Стек

- Backend: Python 3.11+, FastAPI, SQLAlchemy, Alembic.
- Frontend: HTML, CSS и JavaScript.
- База данных: SQLite — журнал операций, связи кампаний с офферами и закреплённые доли.
- Интеграция: Admin API учебного стенда Keitaro.

## Запуск в Windows

Начни в корне проекта. После команды `cd backend` выполняй оставшиеся команды из папки `backend`.

### 1. Создать виртуальное окружение и установить зависимости

```powershell
cd backend
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Команду `Set-ExecutionPolicy` можно пропустить, если PowerShell уже разрешает запуск скриптов.

### 2. Настроить подключение к эмулятору

При первом запуске скопируй пример настроек и открой файл `.env`:

```powershell
Copy-Item .env.example .env
notepad .env
```

Укажи в `backend/.env`:

```env
KEITARO_API_URL=https://keitaro-for-tests.etolegko.com/admin_api/v1
KEITARO_API_KEY=ключ_из_эмулятора
DATABASE_URL=sqlite:///./keitaro.db
DEBUG=true
```

Войди в KT Emulator через GitHub и скопируй ключ кнопкой **«API ключ»**. Храни его только в `.env`: этот файл исключён из Git. Если `.env` уже существует, отредактируй его, не перезаписывая.

### 3. Применить миграции

Оставаясь в папке `backend`, выполни:

```powershell
alembic upgrade head
```

Миграции нужно применить до запуска сервера. Приложение и Alembic читают `DATABASE_URL` из `.env`; запускай обе команды из `backend`, чтобы они использовали одну базу.

Для старой базы, в которой таблицы `campaign_operations` и `campaign_offers` уже созданы, но версия Alembic не записана, один раз выполни:

```powershell
alembic stamp 4e564df2ae2e
alembic upgrade head
```

Если база уже помечена ревизией `4e564df2ae2e`, но таблица `campaign_offer_drafts` уже существует с ожидаемыми полями и ограничением уникальности, сначала выполни `alembic stamp 9c821c3d2f40`, затем `alembic upgrade head`. Текущая ревизия `5a37e1d8f241` добавляет таблицу закреплённых долей офферов.

### 4. Запустить приложение

Из папки `backend` запусти:

```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8001 --reload
```

Если порт `8001` занят или недоступен, выбери другой свободный порт и используй его же в адресе браузера.

Открой [http://localhost:8001](http://localhost:8001). Frontend обслуживается FastAPI, отдельный сервер для него не нужен.

## API

### Состояние и справочники

- `GET /health` — проверка состояния приложения.
- `GET /api/defaults` — офферы, домены, группы, источники трафика и коды стран из эмулятора.

### Кампании

- `POST /api/campaigns` — создать кампанию с двумя потоками.
- `GET /api/campaigns` — получить список кампаний.
- `GET /api/campaigns/{id}` — получить кампанию с потоками.
- `GET /api/campaigns/{id}/offers` — получить офферы, сгруппированные по потокам.

### Офферы и доли

- `POST /api/campaigns/{id}/offers?offer_id=X&stream_id=Y` — добавить оффер в локальный черновик.
- `DELETE /api/campaigns/{id}/offers/{offer_id}?stream_id=Y` — отметить оффер к удалению в черновике.
- `POST /api/campaigns/{id}/offers/{offer_id}/restore?stream_id=Y` — отменить черновое удаление или подготовить возврат оффера.
- `POST /api/campaigns/{id}/streams/{stream_id}/offers/{offer_id}/pin` — закрепить текущую долю оффера локально.
- `DELETE /api/campaigns/{id}/streams/{stream_id}/offers/{offer_id}/pin` — снять закрепление.
- `POST /api/campaigns/{id}/offers/apply` — отправить подготовленные изменения в Keitaro.

Ошибки эмулятора возвращаются с понятным сообщением и статусом. Таймаут запроса возвращается как `504 Gateway Timeout`. Если создание кампании завершилось частично, ответ содержит ID кампании и результат попытки очистки.

## Логика приложения

### Создание кампании

1. Проверить, что ID оффера существует в эмуляторе.
2. Сгенерировать уникальный alias вида `test_<12 символов hex>` и имя `test_<название>`.
3. Создать кампанию.
4. Создать первым поток редиректа на Google с фильтром по стране.
5. Создать вторым поток схемы `landings` с выбранным оффером.
6. Записать операцию в локальный журнал.

Если после создания кампании не удаётся создать поток или записать локальный журнал, приложение пытается удалить частично созданную кампанию. На учебном эмуляторе `DELETE /campaigns/{id}` безвозвратно удаляет кампанию вместе с потоками. Ошибки очистки указываются в ответе.

### Черновики и закрепление долей

Добавление и удаление офферов сначала сохраняются локально и не меняют Keitaro до нажатия «Отправить в Keitaro». При применении приложение читает поток, модифицирует полный массив `offers` и отправляет его через PUT.

Закреплённые доли активных офферов остаются фиксированными. Оставшийся процент распределяется поровну между незакреплёнными активными офферами. Сумма долей должна составлять 100%; недопустимую комбинацию закреплений приложение отклоняет.

Редактировать можно только потоки со схемой `landings`. Потоки редиректа доступны только для просмотра.

### Локальные таблицы

- `campaign_operations` — журнал операций `create`, `add_offer`, `remove_offer`.
- `campaign_offers` — локальная история связей кампания/поток/оффер.
- `campaign_offer_drafts` — неподтверждённые изменения офферов.
- `campaign_offer_pins` — закреплённые доли трафика.

Keitaro остаётся источником актуального состояния кампаний; локально хранятся журнал, история связей, черновики и настройки закрепления.

## Миграции

Команды выполняй из папки `backend` в активированном виртуальном окружении.

```powershell
# Создать миграцию
alembic revision --autogenerate -m "описание"

# Применить миграции
alembic upgrade head

# Откатить последнюю миграцию
alembic downgrade -1
```

## Ограничения учебного стенда

- Приложение работает с KT Emulator, режим заглушек не используется.
- Справочники офферов, доменов, групп и источников доступны только для чтения; создавать офферы через API эмулятора нельзя.
- Эмулятор не предоставляет клики, статистику, лендинги, триггеры, постбэки и отчёты.
- `DELETE /campaigns/{id}` безвозвратно удаляет кампанию и её потоки; архива удалённых кампаний на стенде нет.
- Все секреты должны храниться в игнорируемом Git файле `backend/.env`.
